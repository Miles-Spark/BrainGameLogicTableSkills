# 逻辑图语法

关卡逻辑图是用于描述整个游戏关卡中的逻辑，包括有操作类型和操作后的反馈。

**1.关卡层**

首先逻辑图是一个分层机构；第一层为关卡层，节点名为“Level"+id；

**2.分支层**

 	第二层为分支层，有操作分支和特殊分支，操作分支有操作对象和操作类型以及操作后需要执行的的反馈效果指令，其中操作对象位于整体的第二层, 节点名为”物体类型_等级“。操作类型有点击，双击，滑动（上滑，左滑，右滑，下滑）和拖动，操作类型位于整体的第三层。但是拖动类型比较特殊，因为拖动类型需要两个操作对象，将被拖拽物拖动到触发区域物体上，在第二层上是触发区域物体，而第三层才是被拖拽物体。操作分支位于整体的二三层用于表示操作类型，第四层才是用于表示操作反馈的指令层；

​	特殊分支除操作分支以外的分支，一般是一些操作分支里面通用的逻辑提炼出来避免重复，所以分支下一层就是指令层。

**3.指令层**

指令层是专门用于实现操作反馈的效果，目前已有的指令有

1. 提示指令：每个操作分支开始的第一个指令，用于标识用户操作，格式为“提示+id"。

2. 音效指令：播放音效，格式为”音效+音效名“。

3. 背景音乐指令：播放背景音乐，格式为”音乐+背景音乐名” 或 ”BGM+背景音乐名“。

4. 显示/隐藏指令： 显示/隐藏Unity Scene中的游戏物体表示变化，格式”（显示/解锁）+物品名“,  或者”隐藏+物品名“。

5. 动效指令： 播放spine动画，格式为”动效+动效名“，例如”动效Girl_1_Left“。

6. 升级指令：表示物品的等级变化，其实就是隐藏等级低物体显示等级高物体，例如”Door_1升级生Door_2“, Door是物品类型 ，1是物品等级。
7. 条件指令”：格式为“条件+数字”，例如“条件1”，实际上只是创建一个bool变量，当分支之间有依赖时用于判断，例如分支2里部分效果需要判断分支1是否执行过，如果执行过则触发这段效果，没有则不需要。
8. if 指令：用于创建if 判断表达式，正则匹配格式为”**(?i)^\s\*if\b.\*==**“，示例“if player == 1"。
9. else if指令：用于创建else if 判断表达式，正则匹配格式为"**(?i)^\s*else\s+if\b.*==**"，示例"else if player == 2"。
10. else指令： 创建else与if ，else if指令配合使用,格式为”else"。
11. end指令： 创建end 与if, else if指令配合使用,格式为”end"。
12. 设置变量指令： 用于在分支中创建变量，格式“设置 变量名= 值”, 正则匹配格式为"^设置\s*(\[^\s=]+)\s\*=\s*(.*)$", 示例 "设置 playerLevel =2 "。
13. call指令： 用于在操作分支调用特殊分支，正则匹配格式为”**(?:播放|执行)\w+**“，示例”执行Check“, Check为特殊分支名。
14. 特殊动效组播放指令：格式为”动效组+动效名+[&动效名&数字]“，”[ ]"内容为可选 ，如果只有一个动效名就全部播放这个动效。 示例：动效组Panda_1_Idle&Panda_1_Idle&8, ”动效组“为识别指令的关键字，后面的动效名的格式是”物品名_等级_状态“，其中”物品名_等级“是场景中spine物体的父节点名，动效名还是需要播放动效的名字，第一个动效是需要多个spine一起播放的，第二格动效是需要单独一个spine播放的，所以参数中数字表示第几个spine单独播放。
15. 等待指令：用于延迟下一条指令执行的时机，格式”等待+时间”,例如“等待3s",意思就是延迟3秒。
16. 游戏胜利/游戏失败指令：用于标记游戏的状态是胜利了还是失败了。
